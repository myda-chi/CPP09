PmergeMe explanation file
========================

This file is separate from the implementation code. Its goal is to explain how the program works, why each part exists, and how the data moves through the algorithm.

1) What the header file is doing
--------------------------------

The header file declares the structure of the class and the data that the program needs.

Private member variables:
- _vec: this stores the numbers in a std::vector. It is used for the vector-based version of the sort.
- _deq: this stores the same numbers in a std::deque. It is used for the deque-based version of the sort.
- _timeVec: this stores the time measured for the vector sort.
- _timeDeq: this stores the time measured for the deque sort.

Why these variables exist:
- The subject asks us to sort the same input with both std::vector and std::deque, so we need two containers.
- We also want to print the execution time of each implementation, so we need two timing variables.

Private methods:
- fordJohnsonSortVector(std::vector<int>& arr)
  This runs the Ford-Johnson algorithm on a vector.
- insertLosersJacobsthalVector(std::vector<int>& mainChain, const std::vector<int>& losers) const
  This inserts the smaller values back into the main chain using the Jacobsthal order for the vector version.
- fordJohnsonSortDeque(std::deque<int>& arr)
  This runs the same algorithm on a deque.
- insertLosersJacobsthalDeque(std::deque<int>& mainChain, const std::deque<int>& losers) const
  This does the same insertion step for the deque version.
- generateJacobsthalOrder(int n) const
  This creates the order in which the losers should be inserted.
- getTimeInMicroseconds() const
  This measures the current time so the sorting duration can be computed.

Public methods:
- PmergeMe(), ~PmergeMe(), copy constructor, assignment operator
  These are the canonical class methods. They are needed because the class manages its own data members.
- parseArguments(int argc, char** argv)
  This reads and validates the command-line input.
- sortAndDisplay()
  This is the main workflow function. It prints the input, sorts it, checks correctness, and prints the result and timing.

2) What the source file is doing
--------------------------------

The implementation file is divided into small logical blocks. Each block has one purpose.

A) The helper function parsePositiveInt
--------------------------------------

This function validates one argument before it is stored.

Why it exists:
- The program should accept only positive integers.
- It should reject invalid input such as letters, empty tokens, negative values, or values outside the allowed range.

What it checks:
- If the token is empty, it fails.
- It checks every character one by one. If any character is not a digit, it fails.
- It converts the token into a long long number.
- It ensures that the entire token was consumed, not just part of it.
- It ensures that the number is greater than zero and less than or equal to 2147483647.

Why this is important:
- Without this validation, malformed input could break the program or produce incorrect behavior.

B) The constructors and assignment operator
------------------------------------------

The constructor sets the timing values to zero.
Why:
- Before any sorting is done, the timing values should start at zero.

The copy constructor and assignment operator simply copy the object’s data.
Why:
- The class contains std::vector and std::deque members, so the default copy behavior would not be enough if we wanted correct object copying.
- We manually copy the containers and timing values.

C) getTimeInMicroseconds
------------------------

This function gets the current time in microseconds.
Why:
- We need a precise measurement of how long sorting takes.
- The result is compared before and after the sort to compute the elapsed time.

D) generateJacobsthalOrder
--------------------------

This function builds the Jacobsthal insertion order.
Why:
- The Ford-Johnson algorithm inserts the smaller values, called losers, back into the main chain in a special order.
- The Jacobsthal sequence helps reduce the number of shifts and improves the efficiency of the insertions.

How it works:
- It starts with 0.
- It then builds the next values using the Jacobsthal-style recurrence.
- It uses those values as indices into the losers array.

E) insertLosersJacobsthalVector and insertLosersJacobsthalDeque
---------------------------------------------------------------

These functions insert the losers into the main chain.
Why:
- After the winners are sorted, the smaller values must be inserted back in the correct order.
- The Jacobsthal order makes this insertion process efficient.

How it works:
- It gets the insertion order from generateJacobsthalOrder.
- For each index, it takes the corresponding loser value.
- It uses lower_bound to find the correct position in the current chain.
- It inserts the value there.

F) fordJohnsonSortVector and fordJohnsonSortDeque
--------------------------------------------------

These are the main sorting functions.
They implement the same logic, but on different containers.

The flow inside them is:
1. Check the size.
   - If there is 0 or 1 element, the container is already sorted.
2. Create pairs.
   - Each pair contains one larger value and one smaller value.
   - The larger value becomes the winner.
   - The smaller value becomes the loser.
3. Keep track of a possible straggler.
   - If the number of elements is odd, one element remains unmatched.
4. Recursively sort the winners.
   - The winners form the base of the main chain.
5. Rebuild the mapping between sorted winners and their original losers.
   - This is needed because after sorting the winners, we must still know which loser belonged to each winner.
6. Insert the losers into the main chain using Jacobsthal order.
7. Insert the straggler if there is one.
8. Copy the final sorted chain back into the original container.

Why this works:
- The algorithm builds a sorted structure step by step rather than using a normal merge sort style recursion.
- It is more efficient for this specific insertion-based approach than simply inserting every element one by one.

G) parseArguments
-----------------

This function receives the command-line arguments.
What it does:
- It checks that at least one argument exists.
- It clears the existing vectors and deques.
- It validates every argument using parsePositiveInt.
- If everything is valid, it stores the values in both containers.

H) sortAndDisplay
-----------------

This is the main public workflow function.
What it does:
- It prints the original input.
- It copies the vector data and sorts it.
- It copies the deque data and sorts it.
- It measures the time for both sorts.
- It verifies that both results are sorted.
- It prints the final result and the times.

3) Strong example
-----------------

Take this input:
3 5 9 7 1

Step 1: parsing
- The program reads the values into both _vec and _deq.
- The values become: [3, 5, 9, 7, 1]

Step 2: pairing
- Pair 1: (3, 5) -> winner 5, loser 3
- Pair 2: (9, 7) -> winner 9, loser 7
- There is one odd element left: 1

Step 3: recursive sort of winners
- Winners are [5, 9]
- They are already sorted.

Step 4: map losers to winners
- The sorted winners are [5, 9]
- The losers are [3, 7]
- The main chain starts as [5, 9]

Step 5: insert losers in Jacobsthal order
- The insertion order for two losers is [0, 1]
- Insert 3 first: [3, 5, 9]
- Insert 7 second: [3, 5, 7, 9]

Step 6: insert the straggler
- Insert 1: [1, 3, 5, 7, 9]

Step 7: output
- The sorted array is [1, 3, 5, 7, 9]
- The program prints the result and the measured time.

4) Flow of the whole process
----------------------------

Here is the complete flow in simple form:

1. The program starts in main.
2. main creates a PmergeMe object.
3. parseArguments reads the input and validates it.
4. sortAndDisplay begins.
5. sortAndDisplay prints the initial sequence.
6. It sorts the data with the vector version.
7. It sorts the same data with the deque version.
8. Each sorting function performs the same internal steps:
   - pair values
   - sort winners recursively
   - insert losers using Jacobsthal order
   - insert the straggler if needed
9. The program verifies the order.
10. The program prints the sorted result and the measured times.

5) Why the program uses both vector and deque
---------------------------------------------

The subject requires the same algorithm to be tested on both containers.
This is useful because:
- std::vector is more cache-friendly and often faster for many operations.
- std::deque has different internal behavior and is interesting to compare.

The algorithm is the same, but the container type changes the performance pattern.

6) Summary
----------

The program follows this overall idea:
- validate input
- store it in two containers
- sort it using the Ford-Johnson approach
- use the Jacobsthal sequence to insert the smaller values efficiently
- print the sorted result and the timing information

This is why the code is structured around pairing values, sorting winners, inserting losers, and handling the straggler.
